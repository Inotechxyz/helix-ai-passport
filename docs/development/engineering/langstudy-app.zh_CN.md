# LangStudy 英语学习应用

`PASSPORT ENGLISH` 是运行在 AI Passport 硬件上的离线优先英语学习应用。学习进度保存在设备端，掉电不丢失。配置 Wi-Fi 后，用户可以选择联网刷新单词包，并把进度同步到 Azure Blob Storage。

本应用替换了 demo 菜单和 demo 页面。`main/main.c` 只调用 `ls_app_start()`；所有输入和状态处理位于 `langstudy_app.c`，笔记本风格的界面位于 `langstudy_ui.c`。硬件访问仍保留在 `components/bsp`。

## 约束

- ESP32-C3，8 MB Flash，无 PSRAM，ESP-IDF 5.5.3。
- 240 x 320 ST7789P3 SPI 屏幕。
- GPIO0 上的三个 ADC 梯形按键（UP、OK、DOWN），无触摸屏。
- LVGL 9.5，单块 40 行 DMA 缓冲区，24 KB 内存池。
- 仅支持 ASCII 字体：内容和所有生成字段都拒绝非 ASCII 文本、`|` 和控制字符。
- 内置词包固定为 10 课、100 个单词；刷新时请求生成 6 课、60 个单词。解析器接受 1 到 `LS_WORDS_MAX`（100）之间的任意数量，因此内置词包以及旧固件保存的 100 词词包仍然有效。

## 架构

| 层 | 位置 | 职责 |
| --- | --- | --- |
| BSP | `components/bsp` | 屏幕、按键、电池、音频、I2C、存储封装、睡眠准备。 |
| 纯逻辑 | `main/langstudy_*.c` | 词包/进度解析、排程、音素、合成、JSON、生成结果提取、表单校验；无需 ESP-IDF 即可在主机测试。 |
| 应用 | `main/langstudy_app.c`、`main/langstudy_ui.c` | 启动顺序、输入任务、界面、深度睡眠、联网结果编排。 |
| 服务 | `main/langstudy_provision.c`、`langstudy_deepseek.c`、`langstudy_sync.c`、`langstudy_online.c` | SoftAP 配网页、DeepSeek HTTP、Azure 进度同步、后台任务队列。 |

词包和进度的修改都发生在应用输入任务中。后台服务通过 `ls_online_poll()` 投递堆上分配的结果，界面在合并后负责释放。

## 按键

| 输入 | 动作 |
| --- | --- |
| UP 短按 | 再次朗读当前单词。 |
| OK 短按 | “我会了”：计为正确并前进。 |
| DOWN 短按 | “再显示一次”：计为错误并前进。 |
| DOWN 长按 | 开始或退出当前课程的自动循环播放。 |
| OK 长按 | 打开菜单。 |

自动循环只播放与进入时屏幕上单词 `lesson_id` 相同的单词，因此即使词包包含多课，循环也不会离开当前课程。顶栏进度行显示 `AUTO n / m`，帮助文字上方的细条按设定的停留时间逐渐缩短；进度条走完后切换到下一个单词。停留时间默认 5 秒，可在 `SETTINGS` 的 `WORD DELAY` 中修改。任意按键（包括 DOWN 短按）都会退出自动播放且不计分；长按 OK 会先退出再打开菜单。该模式不会跨重启保留。

菜单项：`REFRESH WORDS`、`PROGRESS`、`BUDDY`、`CREATE PROFILE`、`CONNECTION CHECK`、`SETTINGS`、`PHONE SETUP`、`NEW SESSION`、`BACK`。选择 `REFRESH WORDS` 会打开词库等级列表（`CET4`、`CET6`、`IELTS`）。需要网络的菜单项会显示 `(SETUP)` 并说明缺少什么，而不是静默失败。重置进度放在 `PROGRESS` 内，不再占用主菜单。

`PROGRESS` 始终可用，离线时也能打开。它显示已完成会话数、已作答卡片数、正确率、当前词包中已学单词数以及完成百分比。只有同时具备 Wi-Fi、Azure 容器 SAS URL 和档案时才提供 `SYNC NOW`；否则该行显示 `SYNC NOW (SETUP)` 并说明缺少什么，而不是发起注定失败的请求。其下是 `RESET PROGRESS`：选择后打开确认页，取消或长按 OK 会返回 `PROGRESS` 而不是主菜单。失败状态页在后台任务记录了诊断信息时显示 `DOWN: DETAIL`，按 DOWN 会打开错误详情页，其中包含 HTTP 状态码、可用字节数、重复单词或 HTTPS 错误。

学习界面顶栏只有一行：`PASSPORT ENGLISH`、竖直电池条（从底部按电量填充；绿色，低于 30% 转琥珀色，低于 15% 转红色，电量计从未上报读数时只显示空框）、Wi-Fi 图标和 `D` 徽标。Wi-Fi 与 `D` 图标在连接检查或词包刷新验证过对应链路后出现；两者在结果未知时保持隐藏，后续的离线操作不会清除此前检查得到的绿色图标。它们反映的是最后已知状态，而不是实时连接：每次联网操作结束后无线电都会被关闭。

每次开机、复位和深度休眠唤醒时，只要配置了 Wi-Fi，设备都会启动一次静默链路探测（`LS_ONLINE_PROBE`）。它执行与 `CONNECTION CHECK` 相同的 Wi-Fi、时钟和 DeepSeek 检查，但不打开任何界面，因此学习界面出现几秒后图标才会点亮，在此之前保持隐藏。链路结果绝不会从重置前恢复：重启前保存的值无法说明设备刚刚唤醒后所处的网络。探测仍在进行时用户按下 UP，语音任务会等待它结束（最多约 10 秒），而不是直接回退到离线语音。

唯一跨深度休眠保留的是电池条：休眠前最后一次读数保存在 RTC 内存中，唤醒后先显示该值，再由首个有效读数替换（电量计完成首次转换前，界面每 2 秒重试一次）。断电或重新烧录会清空 RTC 内存，此时电池框为空。只有电芯电压合理（至少 2500 mV）时读数才被采用，因此休眠中或刚重启、返回 `0x00` 的电量计不会被画成 `0%`。

## 启动画面

开机、硬复位和 `esp_restart()` 会在学习界面之前显示 5 秒启动画面。画面上方是对两个女儿的题献（确切字符串只出现在 `main/langstudy_splash.c` 中），下方是 240 x 192 赛博像素风的全家福——父亲、母亲和两个女儿手牵手，背景是霓虹城市，另有加载条和 `LOADING...` 文案。这 5 秒内的任何按键都会被忽略。

初始化在启动画面背后进行：状态加载、音频、语音和联网任务，以及开机链路探测。`ls_ui_init()` 会在移除启动画面之前加载学习界面，因此交接时不会出现黑屏。

深度休眠的按键唤醒**不会**显示启动画面，设备直接回到学习界面。画面由 `tools/gen_splash.py`（Pillow）生成，输出到 `main/langstudy_splash_img.c`，格式为小端 RGB565 加 `lv_image_dsc_t`，LVGL 可直接从 flash 绘制而无需解码器；请重新运行脚本而不是手工修改生成文件。画面逻辑位于 `main/langstudy_splash.c`。如果无法加载任何词包，文案会变成 `NO CONTENT`，题献继续留在屏幕上。

## 用户档案与数字伙伴

`CREATE PROFILE` 会生成随机档案标识，并配对一个数字伙伴。界面可用 UP/DOWN 在 8 个预设名字之间切换；OK 生成 UUIDv4 风格的 36 字符标识和一个随机物种的伙伴，保存后直接打开 BUDDY 界面。已存在档案时，该界面只显示标识：它同时是云同步目录名，静默替换会让远端副本失去归属；`RESET PROGRESS` 会一并删除档案和伙伴。

伙伴有四个物种（`BLOB`、`KIT`、`PIPLING`、`DRAKE`）和四个形态。初始为形态 1，累计 XP 达到 6000、24000、60000 时各进化一次，共三次；在默认等级（4）下，状态良好且全部答对时每张卡片约得 50–55 XP，因此大致相当于 6、22、55 个 20 张卡片的会话，等级更低、答错或状态不佳都会更慢。进化只升不降：即使后续固件调整了阈值，已进化的伙伴也会保留当前形态，不会被降级。每次进化解锁一个技能：

| 形态 | 技能 | 效果 |
| --- | --- | --- |
| 1 | 无 | — |
| 2 | `FOCUS` | 每次答对 +10% XP |
| 3 | `ECHO` | 自动朗读新显示的卡片 |
| 4 | `INSIGHT` | 再 +20% XP（与 `FOCUS` 叠加） |

`ECHO` 朗读的是作答后新显示的当前卡片，而不是刚刚作答的那一张：旧版会在下一张卡片已经显示后才朗读上一张的单词，因此学习者按 DOWN 或 OK 时听起来像是错误的单词自行播放。UP 仍可随时重播当前单词。

答对获得 `10 × 英语等级` XP，因此 `SETTINGS` 中更高的等级（1–10）更值钱。伙伴状态良好（能量至少 60）时再额外获得 25%。答对恢复 2 点能量，答错消耗 2 点，每完成一个会话消耗 5 点。正确率达到 70% 的会话奖励 1 个零食（最多 999 个）。在 BUDDY 界面按 OK 喂食：消耗 1 个零食并恢复 25 点能量；长按 OK 返回菜单。

不学习会损失 XP，但不会退回旧形态。连续 3 天不学习不扣分；之后每多闲置一整天，扣除伙伴剩余 XP 的 1%，因此余额越少扣得越少，且永远不会扣成负数。形态来自持久化的 `stage` 字段而不是由 XP 反推，所以离开几周的已进化伙伴仍保留技能，只是要从更低的余额重新积累下一个形态。作答时会把当前系统时间记为闲置基准；扣分在打开 BUDDY 界面或批改下一张卡片时惰性结算。ESP32-C3 没有带电池的 RTC，刚开机时在网络操作触发 SNTP 之前没有可信时间；早于 2020-09 的时间会被忽略，时钟不可信时不扣分。旧固件写入的记录（没有闲置基准）会在首次结算时从现在开始计算宽限期，而不是追溯补扣。发生扣分时，BUDDY 界面会显示 `IDLE: -<n> XP`。

`BUDDY` 界面把 24x24 调色板像素图以 2 倍绘制到画布，然后显示名字与物种、当前形态、距下一次进化的 XP、能量、零食和当前技能。当前会话的答案、进化和零食会在会话完成页汇总。伙伴状态每次作答后都会保存，掉电最多丢失当前这一张卡片。

档案标识对应 Azure Blob 中的 `<profile id>` 虚拟目录。`SYNC NOW` 会把 `profiles/<profile id>/progress.lsprog` 写入手机配网页配置的容器；详见[进度同步](#进度同步)。

## 数据格式

两种格式都是按行组织的文本，并在 `END` 行携带 CRC32（反射多项式 `0xEDB88320`）；除单词包的 `translation` 为 UTF-8 外，其余字段均为 ASCII。写入端总是重新计算 CRC；解析端会拒绝校验和错误、缺少末尾换行、`CR`、`NUL`、重复 ID 以及越界值。

### 单词包

```text
LSPACK|2|<lesson_count>|<word_count>
LESSON|<id>|<title>
WORD|<id>|<lesson_id>|<text>|<pos>|<meaning>|<translation>|<example>|<pron>
END|<CRC32>
```

`<translation>` 是 UTF-8 中文，且为必填字段；如果某个单词缺少翻译或不包含任何非 ASCII 码点，整个词包会被拒绝。其余字段保持可打印 ASCII。`<pron>` 是以空格分隔的 ARPAbet 字符串，例如 `HH AH L 'OW`；前面的单引号表示主重音。版本 1 词包会被拒绝，设备回退到内置 CET 词包。

学习卡片把 `<pron>` 渲染为 IPA（`/həˈloʊ/`），所用字体为 `main/langstudy_ipa_16.c`，这是生成的 16 px 字体，覆盖 ASCII 以及转换器输出的 IPA 符号。可用 `tools/gen_ipa_font.py` 重新生成（默认源字体为 DejaVu Sans）。`langstudy_phoneme.c` 中的 `ls_pron_to_ipa()` 会把重音符号移动到音节起始位置，并把非重读的 `AH` 映射为 `ə`。为了让 16 px 下更易读，次闭前元音 `ɪ`（U+026A）显示为普通字母 `i`，因此 `AY`/`EY`/`OY` 显示为 `ai`/`ei`/`ɔi`，`IH` 显示为 `i`；`IY` 仍带长音符号（`iː`）。`ER` 始终显示为 `ər`，而不是 `ɝ`/`ɚ`：这两个卷舌元音字形只有 9 px 高，在这个尺寸下会被看成空白竖条，`desert`（`/ˈdɛzərt/`）和 `glacier`（`/ˈgleiʃər/`）正是暴露了这个问题。若不做这些替换，DejaVu 的小型大写 I 和卷舌元音都像是缺失字形。较长的音标会水平滚动，而不是换行。

中文翻译使用 `main/langstudy_cjk_16.c` 渲染，这是生成的 4 bpp LVGL 字体，覆盖 ASCII 和全部 GB2312 字符（7540 个字形，约 906 KiB 位图）。可用 `tools/gen_cjk_font.py` 重新生成；默认源字体是 SIL Open Font License 下的 Noto Sans SC。位图索引上限为 1 MiB，生成器会拒绝超过 20 位索引上限的字库。

### 学习进度

```text
LSPROG|1|<session_count>|<answered_total>|<correct_total>|<record_count>
WORD|<word_id>|<box>|<correct>|<wrong>|<revision>|<due_session>
END|<CRC32>
```

最多保留 256 条记录。记录以稳定的单词 ID 为键，因此调整课程顺序或修改单词文本不会丢失历史。

## 持久化

- NVS 命名空间：`langstudy`。
- 键：`wifi_ssid`、`wifi_pass`、`api_key`、`sync_url`（Azure 容器 SAS URL）、`exam`、`level`、`bright`、`volume`、`word_delay`、`avoid_hist`、`prof_id`、`buddy`。
- 词包使用两个槽位。新词包写入非活动槽，提交后再翻转索引，因此掉电时上一个词包仍然有效。损坏的槽位会在启动时跳过。
- 如果两个槽位都失败，设备回退到内置的 100 词词包（`langstudy_builtin.c`）。
- 每次作答后以及每完成一个学习会话后都会写入进度。
- 伙伴记录同样采用"行文本 + CRC"约定：
  `BUDDY|2|<物种>|<名字>|<形态>|<能量>|<零食>|<xp>|<idle_epoch>|<revision>`，随后是
  `END|<CRC32>`。版本 1 的记录（没有 `idle_epoch`）仍可解析，闲置基准按 0 载入。每次作答、喂食和扣分结算后都会写入。记录损坏时会被忽略；若档案标识仍在，则生成一个新伙伴，避免菜单卡在无法使用的状态。

## 排程

间隔重复使用 0 到 4 号盒子，间隔为 `{0, 1, 3, 7, 14}`：

```text
due_session = session_count + 2 + interval[box]
```

答对前进一个盒子（最多 4），答错回到 0 号盒子。每个会话包含 10 到 20 张卡片，只有会话完成时才增加 `session_count`。设备没有实时时钟，因此所有排程都相对于已完成会话，而不是真实日期。

挑选顺序分三档：到期的复习词（到期最早优先）、未学过的词（从轮换窗口选取，连续会话不会总从同一个词开始）、尚未到期的词。`NEW SESSION` 会把上一个会话的单词 ID 作为排除列表传给选择器，因此连续两个会话的单词集合不同；只有当其余单词不足 10 个时才会复用上一个会话的单词，以保证会话可用，而不是返回过短的集合或 `NO CARDS`。排除列表只保存在 RAM 中，重启后会开始新的轮换。

## 发音

`ls_voice_speak()`（`langstudy_voice.c`）为每个单词选择可用的最佳语音：

- **在线（优先）**：单词文本发送到微软 Edge Read Aloud 神经 TTS，返回的 MP3 边接收边解码播放（`langstudy_tts_edge.c`）。语音为 `en-US-AvaNeural`，格式 `audio-24khz-48kbitrate-mono-mp3`——该接口只接受这一种格式。应用通常会在每次联网操作后关闭射频，因此语音任务会在首次点按时用已保存的 Wi-Fi 凭据重新连接，并在最后一次请求后保持连接 60 秒，连续点按多个单词不会重复付出连接开销。
- **离线回退**：未配置 Wi-Fi、连接或请求失败、或单词没有文本时，由本地共振峰合成器（`langstudy_synth.c`）朗读已存储的 ARPAbet 音素。没有音标数据的单词离线时保持静音，但在线路径使用单词文本，仍然可以朗读。

在线路径运行在独立工作任务（12 KB 栈）上，UI 不会阻塞。点击另一个单词会取消当前语句并替换队列中的请求；在线音频流占用硬件时，离线播放任务会丢弃已排队的单词。

在线传输细节（均在 `langstudy_tts_edge.c`）：

- 基于 `esp_tls` 手写的 WebSocket 客户端（`langstudy_ws_frame.c` 负责 RFC 6455 帧的构造与解析），因为 IDF 5.5 不包含 `esp_websocket_client`。
- `Sec-MS-GEC` 使用 edge-tts 7.3.1 的 v2 CS64 + 改造 SHA-256 令牌；`langstudy_edge_token.c` 逐位复现并由固定测试向量覆盖。该令牌与客户端版本 `2-143.0.3650.75` 及匹配的 `Edg/143.0.3650.75` User-Agent 绑定，微软调整校验时两者必须一起更新。
- MP3 流由内置的 minimp3 解码器（`components/minimp3/`，CC0）解码，混为单声道，再经 `langstudy_resample.c` 的流式线性重采样器从 24 kHz 转为 16 kHz。
- 先建立 TLS 连接，再分配约 16.5 KB 的解码缓冲，以便握手获得最大的连续堆块。任何失败都返回 `false`，调用方回退到离线语音。

离线合成器使用带频谱倾斜的声门源（而非原始锯齿波）、四个共振峰、更宽的擦音带宽与直接噪声分量、塞音的闭塞/爆破/送气、更平滑的共振峰与音高过渡、词尾延长以及直流阻断。UP 会重播当前单词；进入睡眠前应用会停止播放。

## 手机配网

`PHONE SETUP` 菜单项会启动 SoftAP：

1. 设备显示 SSID `LangStudy-XXXX`、密码 `learnXXXX` 以及页面地址 `http://192.168.4.1`。
2. 手机连接该 AP 并打开页面。
3. 页面收集 Wi-Fi SSID/密码、DeepSeek API key 以及可选的 Azure Blob 容器 SAS URL。SAS 字段最多 512 个字符，和 API key 一样只写不回显：留空表示保留已保存的 URL，勾选复选框可删除。该 URL 是凭据，固件不会写入日志，也不会回显。
4. 设备在写入 NVS 之前会先验证站点连接。验证失败会报告原因并且不保存任何内容。
5. 如果已配置 Wi-Fi，设备会立刻运行连接检查，让手机配网结束时就能看到 Wi-Fi/DeepSeek 状态。
6. AP 密码显示在屏幕上，但绝不会写入日志。

已有 SSID 配合空密码表示保留已存密码；新 SSID 配合空密码表示开放网络。

## 联网生成单词

当用户选择 `REFRESH WORDS`，且网络和 API key 可用时：

1. 提示词明确限定输出契约：只返回一个 JSON 对象，仅含 `pack` 字符串，不带 markdown 或说明文字；`LSPACK` 格式必须正好有 6 行 `LESSON` 和 60 行完整 `WORD`，每行 9 个竖线分隔字段。提示词要求随机抽样、覆盖不同主题（不按字母顺序、不重复上一份列表），并给出紧凑的字段长度目标，使完整词包能放进一次响应。它还会列出当前词包中的全部单词（已学过的排在前面）以及近期生成词包的历史单词，并禁止复用这些单词及其复数、时态变体。每次请求都带一个全新的随机种子和 1（入门）到 10（专业）的英语等级。种子会从内置的 48 个领域表中确定性地选出 6 个课程主题（天文学、烹饪、法律、昆虫、银行、电影等），再从另一张表选出 2 种风格/语体（口语词、正式或学术词、感官形容词等）；提示词要求每课使用一个主题，并混入少量对应风格的单词，且始终保持在请求的等级内。因此反复刷新会探索不同的领域和语体，而不只是改变起始字母。风格提示只使用单词类别，因为排除历史以空格分隔，短语动词和习语无法被排除。等级从 `SETTINGS` 中选择的起始值开始，并随会话数与已作答卡片数提高，词频仍随进度变化；格式错误后的重试会把尝试次数混入种子，并附加更严格的警告，避免第二次得到同一批单词。
2. 请求发送到 `https://api.deepseek.com/chat/completions`，模型为 `deepseek-chat`，`response_format` 为 JSON 对象。请求还发送 `temperature` 1.0 和 `top_p` 1.0，以扩大采样范围；JSON 模式、严格的逐行契约、清洗器和单次重试用于控制格式错误或响应过短的风险。（`top_k` 不在 DeepSeek API schema 中，因此不发送。）
3. 响应会被提取并校验，之后才替换活动词包。短响应不会被直接丢弃：如果模型提前停止或附加了说明文字，`ls_gen_sanitize_pack()` 会删除不完整的尾行和模型自带的 `END`，只保留完整的 `LESSON`/`WORD` 行，重写头部计数并追加新的 CRC。它还会逐字段修复，而不是因为一处偏差拒绝整份回复：字段按格式上限截断，常见 Unicode 标点转换为 ASCII；非 ARPAbet 的 `pron` 会先交给 `ls_ipa_to_arpabet()` 转换——IELTS 回复经常无视提示词直接给出 IPA（`/ˈtenənt/`、`/ˈpredʒədɪs/`），转换后这些单词仍可朗读；提示词现在要求 `pron` 非空，转换后仍为空或不可用的 WORD 行会被整行丢弃，而不是保留一张没有音标、也无法朗读的卡片（`ls_pron_validate("")` 对格式本身仍然返回 true，因此旧词包中可能仍有这类单词，但生成路径不再产生它们）；必填字段不可用（单词/释义/中文翻译为空，或字段缺失）的行会被丢弃。至少 30 个可用单词即可接受，这样仍能支持两个会话（20 + 10 个不同单词），因此 IELTS 刷新不会因为响应略短或格式不完全符合而整体失败；少于 30 个可用单词仍然报错。
4. 刷新时按单词文本迁移进度；找不到对应单词的记录会被删除。
5. 被接受的词包中的单词会追加到 NVS 中持久保存的排除历史（`avoid_hist`，1600 字节）。该列表按从旧到新排列，按大小写不敏感去重；新词包放不下时从最旧的单词开始裁剪，因此替换活动词包不会让旧词汇重新变成可复用的候选。首次启用该列表时，会用当前活动词包初始化。`RESET PROGRESS` 会连同进度一起清除该历史；没有存储时仍可刷新，但只排除活动词包中的单词。

为了降低 ESP32-C3 的 SRAM 峰值，HTTP 工作线程以服务器发送事件（`stream: true`）消费响应：每条 `data:` 行被解码，其 `delta.content` 片段在 TLS 记录到达时直接追加到唯一的词包大小缓冲（`LS_GEN_PACK_TEXT_MAX + 512`，16 KiB 加上 `{"pack":"..."}` 包装的余量）中。原始 JSON 响应体从不完整驻留内存；请求体也不再整体分配：Content-Length 用与发送相同的转义规则计算，字节从 256 字节栈缓冲直接写入 socket，因此握手期间只有提示词占用内存。流式接收让字节在长补全期间持续流动，因此每次读取的 120 s 超时只需覆盖两个增量之间的间隔，而不是整个生成过程。DeepSeek 繁忙时会排队请求，首个增量可能超过一分钟才到达，更长的超时避免把这段等待误报为失败。`sdkconfig.defaults` 启用 mbedTLS 动态记录缓冲（每条记录用完后立即释放 RX/TX 缓冲，不再整个会话常驻）、把接收记录保持为 8 KB（服务器证书可能以单条超过 4 KB 的记录到达），并把 Wi-Fi 静态 RX 池缩减为 4 个缓冲（默认 10 个）。静态 RX 缓冲在 `esp_wifi_init` 时分配、驱动不会释放，因此一直占用 TLS、AES-DMA 暂存和词包缓冲都需要的内部 RAM。实测中，8 个静态缓冲时 IELTS 刷新进入响应体阶段只剩 6,272 B 空闲 / 2,048 B 最大连续块，DMA 堆为 4,068 B 空闲 / 1,152 B 最大连续块：AES-DMA 无法分配 1,600 字节暂存缓冲；另一次尝试则因最大连续块仅 14,336 B 而无法分配 16,896 B 的词包缓冲。缩减为 4 个后释放了 6,400 B，连续四次 IELTS 刷新都以约 57–58 KB 空闲 / 30,720 B 最大连续块打开 TLS，每次都成功分配词包缓冲，流式接收期间 DMA 最大连续块仍有 8–9 KiB。动态 Wi-Fi RX/TX 池也各自限制为 8 个缓冲（默认 32 个）：SSE 流式接收期间同时存活的是 16.9 KiB 词包缓冲、动态 TLS 记录缓冲，以及每个在途帧一个 Wi-Fi 缓冲，而 AES-DMA 驱动解密每条记录还需要自己的 DMA 可访问内存。使用默认上限时，CET6 刷新会在流中途以 `ESP_FAIL` 失败，失败位置随已接收内容字节数变化（实测 5677 与 2242 字节）；日志显示 `esp-aes: Failed to allocate memory` 随后是 `esp-tls-mbedtls: read error :-0x7180`，即解密路径已无法从被挤压的堆中分配内存，而读取错误对外表现为 `errno=0`。60 词的目标也让流式文本能放进 ESP32-C3 的 SRAM。刷新路径在 TLS 结束后不再做与内容等大的分配：工作线程完成词包后，用 `ls_pack_scan_view()` 校验并在固定的约 2 KiB 切片索引（`ls_pack_slice_view_t`，BSS）中记录各字段偏移，然后通过结果队列把文本缓冲本身交给 UI。UI 再做一次防御性扫描，按单词文本迁移学习进度，并直接解析进常驻的 25 KiB `state->pack`，最后重新分配稳定 ID。旧固件会在 16 KiB 响应缓冲旁边再分配解析模型（最初 25 KiB，后来是约 15 KiB 的 `ls_gen_pack_t` 暂存模型）；TLS 会话结束后堆总量仍有几十 KB，但最大连续块只有几 KB，IELTS 刷新最终都会失败，报告为 “out of memory for parsed pack (15668 bytes, free=76684)”。扫描与解析器按相同顺序执行完全相同的检查，因此扫描通过的回复在 UI 端不会解析失败；扫描失败（或 UI 端防御性重扫失败）不会改动当前词包和进度。无线开启期间禁用 Wi-Fi 省电模式，因为 modem-sleep 延迟尖峰可能在生成中途被误判为读取超时。被截断（`finish_reason: "length"`）的响应会裁剪到完整行而不是被拒绝；仍然格式错误或可用单词少于 30 个的响应会在状态界面报告失败之前重试一次（换用更严格的提示词并重新混合种子）。复用了排除列表中的单词**不再**视为失败：词包照常接受，状态页显示 `SOME WORDS REPEATED`，按 DOWN 可在详情页看到具体单词。保留新词包比卡在 100% 完成度继续等待下一次生成更实用，下一次刷新会再次通过滚动历史排除这些词。成功提示使用实际接受的单词数，因此被裁剪的短词包会显示如 `45 new words ready`。提示词还会声明设备会强制检查唯一性：重复单词会被丢弃，与排除列表匹配的单词会向学习者报告，以促使模型在回复前检查全部 60 行。HTTPS 打开或写入失败时，日志会记录可用堆和最大连续块；读取失败还会记录 `esp_http_client_read()` 的原始返回值与 mbedTLS TLS 错误码，以及 DMA 可访问堆的剩余量和最大连续块，因为解密在 mbedTLS 内部失败时 `errno` 保持为 0。

当一次会话结束且活动词包中的每个单词都已有进度记录（完成度 100%）时，如果已保存 Wi-Fi 网络和 DeepSeek key，设备会自动发起刷新。每完成一个会话都会提高已学计数，从而抬高下一次请求的有效等级，词包因此被替换成更难的一组，而不是无限循环同一词包。自动刷新失败时照常显示状态页，学习者可以继续学习或从菜单重试。

API key 在手机配网页输入并保存在 NVS。供开发者参考，`.env.example` 记录了 `DEEPSEEK_API_KEY`；固件本身不会读取该文件。

## 连接检查

`CONNECTION CHECK`（手机配网后也会自动运行）逐段报告状态，而不是给出一个笼统的错误：

1. 站点加入后显示 `Wi-Fi: OK  <ssid>`，否则显示 `Wi-Fi: FAIL (<err>)`。
2. SNTP 成功后显示 `Clock: OK`，因为 TLS 证书校验需要合理的时钟。
3. 使用已保存的 key 请求 `GET https://api.deepseek.com/models` 并返回 HTTP 200 时显示 `DeepSeek: OK`。该探测不消耗生成额度；其他状态显示为 `DeepSeek: HTTP <code>` 或 `DeepSeek: FAIL (<err>)`。

刷新失败时 `ESP_ERR_HTTP_CONNECT` 会映射为 `Cannot reach DeepSeek (Wi-Fi/TLS)`，串口日志会带上 `errno` 和堆水位。

## 进度同步

只有同时具备 Wi-Fi、手机配网页保存的容器 SAS URL 和 `CREATE PROFILE` 创建的档案时才会同步。同步从 `PROGRESS` 界面启动；缺任一项时该行显示 `SYNC NOW (SETUP)`，状态页会指出缺少什么。

### Azure 目录结构

配置值是容器 SAS URL，例如
`https://ACCOUNT.blob.core.windows.net/CONTAINER?sv=...&sig=...`。Blob 存储没有真正的目录：设备写入一个路径形式的 blob 名，因此门户中会看到 `profiles/<profile id>/` 目录：

```text
CONTAINER/
  profiles/
    12345678-abcd-4f01-9ead-beef0badf00d/
      progress.lsprog
```

`progress.lsprog` 就是本地使用的 `LSPROG` 文本（`text/plain`）。容器必须已存在；SAS 需要读、创建和写权限（`sp` 包含 `r`、`c`、`w`），并应限制为 HTTPS（`spr=https`）。可在门户的 **容器 → 共享访问令牌** 中生成，或使用：

```sh
az storage container create --account-name ACCOUNT --name CONTAINER
SAS=$(az storage container generate-sas --account-name ACCOUNT \
  --name CONTAINER --permissions rcw --https-only \
  --expiry 2027-01-01 -o tsv)
echo "https://ACCOUNT.blob.core.windows.net/CONTAINER?$SAS"
```

把输出的完整 URL 粘贴到手机配网页。重新生成令牌后，用新的完整 URL 替换已保存的值。

该 URL 是持有者凭据，和 API key 一样保存在 NVS 中；固件从不打印它，也不会把它放进状态页或日志。失败时只报告 `HTTP 403`（SAS 过期或错误）、`HTTP 404`（容器不存在）或传输错误。

### 合并顺序

同步采用读—合并—写，而不是服务端合并：

1. 用 `x-ms-version` 和 `x-ms-date` 请求 `GET profiles/<id>/progress.lsprog`；由于 Azure 会拒绝过期日期且 TLS 需要时钟，会先运行 SNTP。
2. `404` 表示该档案首次同步，合并结果就是本地快照；其他非 200 状态会带着状态码中止。
3. 把远端文档合并到本地快照的副本中。本地始终是权威来源：单词记录的 `revision` 更高时获胜，相同时保留本地副本；新的单词 ID 在表未满时追加；`session_count` 和计数采用已完成会话更多的一方。
4. 用 `PUT` 写回合并结果，类型为 `BlockBlob`（`x-ms-blob-type: BlockBlob`）。新建 blob 返回 `201`，覆盖返回 `200`。
5. 界面把返回的快照再次合并到实时状态（幂等）并保存。

GET 响应和 PUT 请求体复用同一个 20 KiB 缓冲区，避免在 TLS 占用内存时再分配一块大缓冲。当前假设一个档案只由一台设备同步，没有 ETag/`If-Match` 重试；若两台设备同时同步，后写入者获胜，但下一次同步会按 revision 合并另一台设备的记录。

## 电源管理

- 无输入 30 秒后屏幕变暗。
- 无输入 300 秒后进入深度睡眠。
- 有按键被按住时拒绝进入深度睡眠，避免卡键导致立即唤醒循环。
- 唤醒后，按键守卫会等待松开再接受新的按键。
- 睡眠顺序遵循 BSP 约定：先停止音频和服务，准备按键交接，启用 GPIO 唤醒，然后依次让电池、音频、I2C 和屏幕进入睡眠。

## 真机验收清单

1. 无网络启动：先出现 5 秒启动画面，显示题献和全家福；随后加载内置词包并显示 20 张卡片中的第一张。深度休眠按键唤醒后不得出现启动画面。
2. 回答多张卡片，断电重启，确认盒子与计数恢复。
3. 长按 OK：菜单打开；UP/DOWN 移动高亮，OK 选择。
4. 按 UP：当前单词可听见；睡眠时音频干净停止。
5. 选择 `PHONE SETUP`：AP 出现、页面可打开，只有设备成功加入后才保存网络；随后自动运行连接检查。测试失败时页面会指出原因（`Wi-Fi not found`、`Wrong Wi-Fi password` 或驱动错误码），并且不保存任何内容。
6. 选择 `CONNECTION CHECK`：屏幕分别显示 Wi-Fi、时钟和 DeepSeek 状态；使用有效 API key 时显示 `DeepSeek: OK`。检查成功后，学习界面顶栏右侧出现 Wi-Fi 和 `D` 图标；同一行还显示 `PASSPORT ENGLISH` 和竖直电池条（电量计从未上报读数时为空框）。两者都配置好时，每次重启和深度休眠唤醒后无需任何操作，图标也会在几秒内自行出现。
7. 学习卡片的顺序为单词、音标、中文翻译；翻译最多换行两行且不与词性重叠。
8. 发音行渲染为 IPA（例如 `/həˈloʊ/`），而不是原始 ARPAbet；较长的音标水平滚动。`climate` 显示为 `/ˈklaimət/`，`recycle` 显示为 `/riːˈsaikəl/`，双元音中的 `i` 清晰可见，而不是空白竖条。`desert` 显示为 `/ˈdɛzərt/`，`glacier` 显示为 `/ˈgleiʃər/`，结尾的 `ər` 清晰可见。
9. Wi-Fi 已连接时点按单词：神经语音朗读单词文本，串口日志出现 `ls_edge_tts` 的堆内存与播放记录。断开 Wi-Fi（或走出覆盖范围）后再次点按：同一个单词改由离线合成器朗读。快速连续点按多个单词时，上一个单词会立即停止，而不是排队依次播放。
10. 选择 `REFRESH WORDS`：出现 `CET4`、`CET6`、`IELTS` 的二级列表。如果尚未保存 Wi-Fi 网络或 DeepSeek key，设备会立即显示 `WI-FI OR DEEPSEEK NOT SET UP`，不会发起网络请求。选择某个等级后会请求 6 课、60 词的随机新词包，且不与当前词包及近期生成历史共享任何单词（已学过的单词优先排除），每次使用新的随机种子，有效等级随学习进度提升。至少 30 个完整单词的短响应会被裁剪后接受；格式错误的响应会使用更严格的提示词重试一次。若接受的回复复用了排除列表中的单词，词包仍然生效：状态页显示 `SOME WORDS REPEATED`，`DOWN: DETAIL` 会列出具体单词。连续刷新应显示不同的课程主题/标题和风格组合，格式错误导致的重试应保持偶发。成功提示显示实际接受的单词数（通常为 `60 new words ready`）。失败状态页会提供 `DOWN: DETAIL`，显示后台任务记录的诊断信息。当 `PROGRESS` 中的完成度达到 `100%` 且一次会话结束时，只要已配置 Wi-Fi 和 DeepSeek key，设备会自动刷新，状态页显示 `ALL WORDS STUDIED / REFRESHING <等级>`；由于多完成了一个会话，新词包的有效等级也会更高。
11. 选择 `SETTINGS`：UP/DOWN 在 `ENGLISH LEVEL`、亮度、音量和 `WORD DELAY` 之间移动，OK 进入调整模式，UP/DOWN 改变数值，长按 OK 退出或保存。四个数值都能在断电重启后保留。`ENGLISH LEVEL` 为 1（入门）到 10（专业），默认 4，是取词的起始等级；进度会让有效等级高于它。`WORD DELAY` 是自动播放的停留秒数（默认 5）。标题行显示固件版本（`version.txt` 中的 `v<semver>`），底部显示编译时间，两者都来自应用描述符，便于根据设备截图定位到具体固件。
12. 在学习卡片上长按 DOWN 开始当前课程的自动循环：进度行显示 `AUTO n / m`，细条按停留时间走完后自动切换到下一张卡片。再次长按 DOWN（或按任意其他键）退出；长按 OK 退出并打开菜单。循环不得离开当前课程，也不得改变会话得分。
13. 选择 `PROGRESS`：界面显示会话数、已作答卡片数、正确率、已学单词数和完成百分比。具备 Wi-Fi、SAS URL 和档案时，`SYNC NOW` 会在容器中创建 `profiles/<profile id>/progress.lsprog` 并显示 `Progress synced`；再次同步会覆盖同一个 blob。缺项时该行显示 `SYNC NOW (SETUP)`。
14. 连续完成两个会话，确认词包单词足够时第二个会话不会重复第一个会话的卡片。
15. 保持空闲：30 秒后屏幕变暗，5 分钟后睡眠；按键可唤醒。
16. 选择 `PROGRESS` 再选 `RESET PROGRESS`：出现确认页；取消或长按 OK 会返回 `PROGRESS`。确认后所有学习记录、近期生成的排除历史、档案及其伙伴都会被清除并开始新会话，当前词包保留。
17. 选择 `CREATE PROFILE`：UP/DOWN 切换预设名字，OK 后进入 BUDDY 界面，显示精灵图（融入纸色背景，没有黑色方块）、形态、距下次进化的 XP、能量和零食。作答后确认伙伴获得 XP（英语等级越高越多，能量至少 60 时再增加 25%）。有零食时按 OK 喂食；长按 OK 返回菜单。断电重启后确认档案标识、名字、物种和 XP 均恢复。正确率至少 70% 的会话会奖励 1 个零食。
18. 时钟已同步时，把设备时间推过 3 天宽限期（或恢复一条 `idle_epoch` 更早的伙伴记录）后打开 BUDDY：标题行显示 `IDLE: -<n> XP`，每多闲置一天扣除 1%，形态和技能保持不变。紧接着再次打开 BUDDY 不会重复扣分。

## 已知限制

- DeepSeek 输出具有随机性；词包校验器只能保证格式与内容合法，不能保证教学质量。`temperature` 1.0（DeepSeek 默认值）仍高于原来的 0.5，会提高格式错误、响应过短或重复词较多的概率，因此自动重试可能更频繁。
- 主题提示只能引导领域，无法保证每个单词都落在请求的词频区间内，等级 1–3 尤其明显。
- 闲置扣分需要可信的系统时钟。设备始终离线（或在任何 SNTP 同步前就断电）时不会扣分；这是没有电池 RTC 所接受的取舍。
- 进度同步依赖容器 SAS。该 token 是唯一凭据：应只授权一个容器、仅允许 HTTPS、设置有限有效期，并在过期前重新生成（在手机配网页重新保存）。固件只在 NVS 中保存 URL，因此恢复出厂设置或 `RESET PROGRESS` 都不会吊销 SAS。
- 伙伴状态只保存在本机，同步上传的只有 `progress.lsprog`。使用同一档案标识的另一台设备会共享学习历史，但伙伴从新状态开始。
- 共振峰合成器比早期版本更清晰，但仍属合成音，现在只是离线回退方案。
- 在线发音依赖微软未公开文档的接口；`Sec-MS-GEC` 令牌、客户端版本和 User-Agent 彼此绑定，服务端一旦调整，设备会静默回退到离线语音，直到更新 `langstudy_tts_edge.c` 中的常量。
- 在线发音在最后一次点按后仍保持 Wi-Fi 开启 60 秒，避免每次点按都重新连接；因此使用神经语音学习时功耗明显高于纯离线路径。
- TLS、音频启动和深度睡眠唤醒的真机时序必须在硬件上测量，主机测试无法覆盖。
